# 画面録画 進行台本

課題提出用の画面録画で「何を見せるか」「何を話すか」をまとめた台本。上から順に操作すれば一通りのデモになる。

URL: https://d2lvrrryjxvijh.cloudfront.net (AWS本番環境)

---

## 0. 導入(30秒程度)

話す内容:
- アプリ名・概要:「対戦ポケモンのパーティ構築とダメージ計算を行う個人開発ツール」
- 非公式ファンツールであり、Nintendo/Game Freak/The Pokémon Companyとは無関係である旨に軽く触れる
- 技術スタックを一言で:「学校指定の技術(React/TypeScript/Vite/Tailwind/Java/SpringBoot/Gradle/PostgreSQL)をあえて使わず、Svelte/FastAPI/MySQL等の代替技術で構築し、AWS(EC2+RDS+S3+CloudFront)にデプロイした」

## 1. パーティ構築タブ

1. 「パーティ構築」タブを開く
2. 種族検索欄に日本語でポケモン名を入力(例:「マスカーニャ」)→検索候補が出ることを見せる
3. 候補を選択 → 詳細(タイプ・特性候補)が表示されることを見せる
4. 持ち物・特性・性格を選択
5. 努力値をプルダウンで選択(0〜32段階)→ 実数値がリアルタイムで変わることを見せる
   - 話す内容:「このゲーム独自の努力値仕様(0〜32段階、性格補正の掛かり方が非対称)を実機データから解析して実装した」
6. 技を4つ選択(タイプ別に色分けされたドロップダウン)
   - 話す内容:「技をタイプごとに色分け・グルーピングして選びやすくした」
7. パーティに保存 → 一覧に反映されることを見せる
8. 保存したパーティを編集・削除できることを見せる

## 2. ダメージ計算タブ

1. 「ダメージ計算」タブを開く
2. 攻撃側・防御側のポケモンを設定(種族・努力値・性格・持ち物・技)
3. 天候・トリックルーム・急所などのトグルを1つ操作して結果が変わることを見せる
4. ダメージ乱数幅・確定数(何発で倒せるか)が表示されることを見せる

## 3. AWS本番環境であることの証明

1. ブラウザのアドレスバーの URL (`https://d2lvrrryjxvijh.cloudfront.net`) を指して「ローカルではなく実際にAWSにデプロイされた環境で動いている」ことを明示
2. (任意)ブラウザの開発者ツール Network タブで `/api/...` へのリクエストが200で返っていることを一瞬見せる

## 4. アーキテクチャ・技術選定の説明(1〜2分)

話す内容の骨子(詳細は `docs/tech-stack-rationale.md` 参照):
- 構成:「CloudFront(HTTPS配信)→ S3(フロント静的ファイル) / EC2(FastAPI, Nginx+systemd) → RDS for MySQL(分離サブネット)」
- なぜEC2+RDSか:「Elastic Beanstalkやサーバーレスではなく、あえて素のEC2を選び、OSセットアップ・systemdでのプロセス常駐化・Nginxのリバースプロキシ設定を自分の手で行った」
- なぜSSM Session Managerか:「SSH鍵や22番ポート開放を行わず、AWS Systems Manager経由でインスタンスを運用している」
- なぜMySQLか / なぜFastAPIか / なぜSvelteか:「学校で習ったJava+SpringBoot+PostgreSQL、React+TypeScript+Viteの代替として、それぞれの設計思想の違いを説明できることを基準に選定した」
- コストについて:「個人開発のため無料利用枠に完全に収まる構成にし、想定外の課金に気づけるようAWS Budgetsでアラートを設定している」

## 5. 締め(10〜20秒)

- GitHubリポジトリURLを画面に出す(または口頭で伝える)
- 「今後は相手の行動予測や勝率推定などの機能を追加していく予定」と触れて終了
